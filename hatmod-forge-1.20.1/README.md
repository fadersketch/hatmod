# 神之牛仔帽 · Forge 1.20.1

三顶**牛仔帽**（黑 / 白 / 红）外加三顶合一的**「全」**。机制相同，数值和专属效果各不相同；
「全」把三种专属效果与全部专属附魔都收进一顶。

- Minecraft **1.20.1**
- **Forge 47.4.26**（`[47,)` 均可）
- Java 17

> 同一模组的 NeoForge 1.21.1 版本在 `../hatmod-neoforge-1.21.1/`。

---

## 四顶帽子的数值

| 帽子 | 蓄力 | 照射 | 每刻附加伤害 | 专属效果 |
| --- | --- | --- | --- | --- |
| **黑色** | 22 秒（440 刻） | 8 秒（160 刻） | **10** | 蓄力期间**受到伤害就瞬移躲开那一击（完全免伤）**，每轮最多 3 次（末影系传送特效+音效，起点到落点拖一整条粒子路径 + 屏幕提示剩余次数） |
| **白色** | 18.2 秒（364 刻） | 6.45 秒（129 刻） | **10** | **永久迅捷 I + 跳跃 I** |
| **红色** | 29.4 秒（588 刻） | 7.6 秒（152 刻） | **10** | 照射期间**力量 I** |
| **全** | 随路线 | 随路线 | 黑 12 / 白 10 / 红 15 | **黑 + 白 + 红三种专属效果始终同时生效**（瞬移闪避 + 力量 + 永久迅捷/跳跃），**兼容全部 9 个专属附魔**，且不附魔也自带附魔光效。**每轮从黑/白/红里随机取一条路线**（随机不重复）→ 时长、BGM、粒子颜色、帧伤、帽子颜色全按那条路线走 |

> 「全」由**三顶原色帽在工作台合成**得到（见下），合成时三顶帽子上的**附魔全部继承**、同一附魔取最高等级。
> 它是唯一能同时附上「闪避 / 残影 / 预知 / 缓速 / 疾行 / 光辉 / 掌控 / 吸血 / 光柱」全部 9 个专属附魔的帽子。
>
> **「全」的路线机制**：三顶原色帽的时长/帧伤/音乐各不相同，而「全」把它们**串成一条链**——
> 每轮开火随机取一条（黑/白/红，三条走完才重洗，不会连着两次同色），本轮就完全是那顶帽子的
> 手感：**黑路线** 22s 蓄力 + 8s 照射 + 帧伤 12 + `music_black`；**白路线** 18.2s + 6.45s + 10 + `music_white`；
> **红路线** 29.4s + 7.6s + 15 + `music_red`。同时**身上的帽子会变成那个颜色**（护甲贴图、光柱颜色一起跟着变），
> 一目了然这轮在走哪条。三种专属特性（闪避/力量/永久增益）**不跟路线走，始终同时生效**；
> 9 个专属附魔也都照常生效（附魔效果三条路线都吃得到）。所以「全」不再需要 `music_all` 那首串烧了。

> 每刻附加伤害是**生存向的低值**，光柱真正的压力来自「每刻扣目标当前生命的 5%」那一部分
> （`HatSettings.DEFAULT_HEALTH_DAMAGE_RATIO`），固定值只负责收尾。
>
> ⚠️ 改这里的默认数值时，**必须同时把 `HatSettings.CONFIG_VERSION` 加一**：`config/hatmod.json`
> 一旦存在就会一直盖住默认值（「改了默认值但游戏里没变化」就是这个原因）。加了版本号之后，
> 旧文件会在加载时被识别为过期并整份丢弃，自动换用新默认值 —— 不需要让人手动去删文件。

数值集中在一个地方：`src/main/java/com/hatmod/HatType.java`。

四顶帽子在游戏里统一叫**「神之牛仔帽（黑/白/红/全）」**，物品提示写着**「神本无相」**
（「全」单独用一行**「新神已至」**）。文本在 `assets/hatmod/lang/{zh_cn,en_us}.json`：
`item.hatmod.hat.desc`（三顶原色帽共用）、`item.hatmod.all_hat.tagline`（「全」专用）、
`item.hatmod.all_hat.desc`（说明「全」在哪）。

**「全」的物品名是固定金色**（`ChatFormatting.GOLD`，原版那档橙金）且**不受附魔影响**：
原版渲染名字时是把稀有度颜色套在外层，而附魔会把稀有度提升一档（COMMON/UNCOMMON→RARE、
RARE→EPIC），名字就会被染成水蓝/淡紫；`HatItems` 里覆写了 `getName(ItemStack)`，给「全」的
名字本体显式设上金色，子级样式优先，所以附魔压不过它。三顶原色帽照原版规矩走。

### 合成表

三顶原色帽都是**有序合成**，原来空着的 4 个格子全部填上**下界之星**：

```
L L L
L D N
N N N
```

`L` = 皮革 ×4，`D` = 对应颜色的染料（黑/白/红），`N` = 下界之星 ×4。

| 项 | 位置 |
| --- | --- |
| 配方文件 | `data/hatmod/recipes/{black,white,red}_hat.json` |

**「全」是特殊合成**：黑帽 + 白帽 + 红帽（**无定形**，摆哪三个格子都行）→ 神之牛仔帽（全）。

| 项 | 位置 |
| --- | --- |
| 配方文件 | `data/hatmod/recipes/all_hat.json`（内容只有 `{"type": "hatmod:hat_fusion", "category": "equipment"}`） |
| 配方实现 | `src/main/java/com/hatmod/HatFusionRecipe.java`（继承 `CustomRecipe`，附魔合并逻辑在这里） |
| 序列化器 | `src/main/java/com/hatmod/HatRecipes.java`（注册名 `hatmod:hat_fusion`） |

> 之所以做成 `CustomRecipe` 而不是普通 shapeless：普通配方的结果物品栈是写死的，
> **没法把三顶帽子上的附魔继承到产物**；`assemble()` 现算才能做到「附魔全部带走」。

> 1.20.1 的目录名是**复数** `recipes`（1.21.1 是单数 `recipe`）——目录名写错配方会被静默忽略、
> 合成表里什么都查不到，改的时候注意别搞混。

## 机制：一个完整的循环

戴上牛仔帽（头盔槽）后进入自动循环。**任何生物**戴上都会生效——
玩家、车万女仆、其他模组的生物都一样。

```
        ┌──────────────────────────────────────────────────┐
        │                                                  │
        ▼                                                  │
  ① 合法目标进入 24 格（光柱射程；没有目标就不会进入蓄力）          │
        │                                                  │
        ▼                                                  │
  ② 蓄力（黑 22s / 白 18.2s / 红 29.4s；「全」随本轮路线取其一）  │
     · 【循环开始】播放这顶帽子的音乐（位置在戴帽者身上、可衰减）     │
     · 索敌与攻击照常（蓄力不再禁止攻击，也不再压制索敌）              │
     · 自身以外 5 格内：生物缓慢 V + 整体压速（时间变慢，方向不变）    │
     ·            　 　 箭矢等弹射物关掉重力、沿原方向极慢飞行        │
        │                                                  │
        ▼                                                  │
  ③ 蓄力结束的瞬间                                            │
     · 范围减速**全部解除**，周围生物立刻恢复自由                  │
     · 戴帽者照常可以打敌人（蓄力期也没被禁过）                   │
     · 获得「迅捷 II」（到循环结束）+ 信标音效                   │
        │                                                  │
        ▼                                                  │
  ④ 持续照射（黑 8s / 白 6.45s / 红 7.6s；「全」随本轮路线）     │
     · 光柱【每道各锁一个不同的敌人】，更近的会顶掉旧的（会转火）      │
     · 被光罩住的敌人每刻吃「按血量算」的伤害（见下方公式，无视护甲）  │
     · 同时获得「缓慢 255」，完全动不了                          │
     · 红帽：期间自身力量 I                                     │
        │                                                  │
        ▼                                                  │
  ⑤ 附近还有敌人？ ── 是 ──> 回到 ②（循环开始，音乐重放）──────────┘
                   └─ 否 ──> 回到待机（音乐停止）
```

**注意**：蓄力阶段与照射阶段是明确分开的两段。时间差力场和攻击封锁**只存在于蓄力阶段**；
蓄力一结束就全部撤掉，此时你能自由攻击，怪物也不再被拖慢（但被光柱照到的仍会被定身）。

### 「全」的路线机制（它每轮「变成」某一顶原色帽）

「全」没有自己固定的时长/帧伤/音乐，而是每轮从**黑/白/红**里取一条**路线**，本轮完全按那条走：

| 本轮路线 | 蓄力 | 照射 | 每刻帧伤 | BGM | 帽子颜色 |
| --- | --- | --- | --- | --- | --- |
| 黑路线 | 22 秒 | 8 秒 | **12** | `music_black` | 黑 |
| 白路线 | 18.2 秒 | 6.45 秒 | **10** | `music_white` | 白 |
| 红路线 | 29.4 秒 | 7.6 秒 | **15** | `music_red` | 红 |

- **怎么取**：三条路线**打乱后依次取**，取空再重洗（Fisher-Yates）—— 所以是**随机但不重复**：
  三条各走一遍才会重复，中间不会连着两次同色。重洗时还会避开「新袋第一条正好等于上一轮」，
  免得洗牌边界上出现连续同色。实现在 `HatAbilities.nextRoute`，袋子和下标存在 `HatState.routeBag`。
- **颜色怎么变**：路线一变就发一条 `RouteMessage`（S2C）给看得见的人，客户端存进
  `HatRouteState`。护甲槽那条渲染路走 `IForgeItem#getArmorTexture`（在 `HatItems` 里重写），
  饰品栏那条路走 `CurioHatRenderer` 自己查一次路线；**光柱淡色**也读同一份路线。
  取不到路线（还没收到包）时退回「全」自己的三色贴图，不会花屏。
- **三种专属特性不跟路线走**：瞬移闪避 / 照射期力量 / 永久迅捷+跳跃**始终同时生效**，
  判定读的是 `state.type`（= ALL）而不是 `state.route`。
- **9 个专属附魔照常生效**：附魔判定也走 `state.type`，所以三条路线都吃得到全部附魔。
- **帧伤为什么不走调参器**：路线帧伤写在 `HatType.routeDamage`（黑 12/白 10/红 15）里，
  调参器里「全」那一栏的数值只是占位；`chargeTicks`/`flashTicks` 同理（用的是路线那顶的）。

### 音乐

- **每次循环开始（进入蓄力）时播放**该帽子对应的曲子：
  黑 `music_black`、白 `music_white`、红 `music_red`（`assets/hatmod/sounds/`）。
  **「全」不单独放曲**：它每轮随机取一条路线，就放**那条路线**对应的曲子
  （黑路线放 `music_black`、白路线放 `music_white`、红路线放 `music_red`）——
  和它的时长、颜色、帧伤是同一套。所以「全」打起来三首 BGM 会轮流响，正好对上身上的帽色。
- 声音绑定在**戴帽者身上**、属于 `PLAYERS`（玩家）声道，因此**跟着人走、有距离衰减**，
  和玩家自己发出的声音等效；附近的人靠近听得清、远处渐弱。
- 循环被打断（摘帽 / 死亡 / 换帽 / 没有合法目标）时音乐立即停止。
- 三首曲子的长度刻意与各自的循环对齐（黑约 30 秒 / 白约 24 秒 / 红约 37 秒），
  所以正常连打时几乎是无缝循环 —— 只要**循环总长不短于曲子**（短了会两遍叠着响）。
- **同时只听一条（默认开启）**：多条 BGM 同时响会很吵，所以默认开启「自己的 BGM 优先」
  （调参器右上角的开关，也会落盘到 `config/hatmod.json` 的 `ownBgmPriority`）：
  - **自己的 BGM 绝对优先** —— 自己正在放，就只听得见自己那条（哪怕它的声道此刻正好被重建）；
  - 自己没在放时，**只留最后响起的那一条**；后起的那条停了（例如那个玩家死了），
    前面那条会**从中途接着响**（不是从头重播）。
  - 关掉这个开关就恢复原版行为：所有 BGM 照播、任由重叠。
- **「服务端说到停才停」**：客户端记的是「**应该响着的那些 BGM**」，不是「此刻活着的声道」。
  声音实例被掐掉（曲终 / 音效引擎重载 / 被别的音效挤掉）时不是丢掉这一条，而是**原地重建接着放**；
  只有服务端明确发来「停了」、或者戴帽者实体已经不在客户端世界里，才会真正移除
  —— 所以不会再出现「玩着玩着 BGM 突然没了」。
- 三首曲子按**非流式**（`"stream": false`）加载：原版的流式声道是**单独一个名额很少的池子**，
  连原版自己的背景音乐都在里面抢；帽子 BGM 是最长的那一类声音，挤在流式池里会
  把玩家自己的 BGM 挤掉。改成非流式（三首都是单声道、总共不到 10 MB）就只占普通声道池，
  不再和音乐抢位置 —— 这也是「给玩家的 BGM 更高的优先级」的一半。
> 实现上由**客户端**自己播放，服务端只发「谁的 BGM 开始 / 停了」。原版的声音包不带
> 「这条音乐属于哪个实体」，做不到按听者取舍；顺带修掉了「停一个人把同色帽子的另一个人
> 也一起掐掉」的老毛病。

### ① 和平主义（一直生效，与循环无关）

戴上帽子后**无法攻击被动生物**（牛羊猪鸡兔猫…）和**未被激怒的中立生物**
（狼、羊驼、铁傀儡、蜜蜂、末影人、僵尸猪灵…）。

- 敌意生物（僵尸、骷髅、苦力怕…）**照常可以攻击**。
- 中立生物被激怒后、或已经锁定你时，**可以攻击**。

这一条是帽子本身的属性，一直生效，不随蓄力 / 照射切换。

### ② 蓄力阶段

**合法目标进入 24 格**（`FLASH_RANGE`，光柱射程）即开始蓄力（一个合法目标都没有时不会进入蓄力）。

「合法目标」由 `HatAbilities.isEnemy` 一个函数说了算，**四类都算**：

| 算合法目标 | 说明 |
| --- | --- |
| 敌意生物 | 僵尸、骷髅、苦力怕…（`Enemy`） |
| **被激怒的中立生物** | 狼、羊驼、铁傀儡、蜜蜂、末影人、僵尸猪灵…只要怒气还没消（`NeutralMob#getRemainingPersistentAngerTime > 0`）就算，不需要它正在打你 |
| 正在锁定戴帽者的生物 | 不看类型：`getTarget()` 指向戴帽者就算 |
| **最近真的打过戴帽者的生物** | 兜底：对戴帽者造成了**大于 0 的伤害**之后，**10 秒**（`AGGRO_MEMORY_TICKS`）内一律算敌人 |

> 最后一条是给「名义上不是敌人、实际上会动手」的生物兜底 —— 例如被魔改过的**野生女仆**，
> 分类上是被动生物、连中立都不算，却真的会打人。判据只看结果：**打掉过血**才算。
> 记忆有时效，不会记一辈子。
>
> - **伤害为 0 的「攻击」不算**（打雪仗那种推一把的雪球就是 0 伤害），所以玩闹不会进名单。
> - **己方永远除外**（主人本人、同一主人的女仆/宠物、同一队伍的成员）——
>   就算自己的女仆真把你打掉血了，也不会被光柱锁上。这一条排在兜底之前。
> - 玩家也永远不算（`isEnemy` 第一句就挡掉），免得光柱对着别人乱扫。

这几类目标一旦进名单，**蓄力照常触发**，之后**每道光柱也会正常锁它、照它** ——
判定和锁定走的是同一个 `isEnemy`，不存在「能触发蓄力但打不到」的情况。

- **没有「蓄力期间禁止攻击」这回事了**（这条已删去）。玩家近战由 `AttackEntityEvent` 拦、
  其他生物与远程（弓箭、投掷物）由伤害事件拦，拦的**只有**上面「和平主义」那一条：
  不能打被动生物与未激怒的中立生物。被光柱强控的生物仍然一点伤害都打不出来 ——
  那是控场效果本身，不是戴帽者的读条代价。
- **索敌照常**：戴帽的生物（玩家、女仆等）在蓄力 / 照射期间正常选目标、正常追人。
  早先那条「蓄力期间让戴帽生物丧失索敌欲望」的实现（每刻清 `Mob#target`、并拦它重新锁定）
  已经删掉了 —— 现在只剩控场本身还会拦目标：被「神隐」的目标锁不上，
  「掌控」则把受害者的目标换成我们指给它的那个对手。
- 以自己为中心、**半径 5 格内**，除自己以外：
  - **生物**：**缓慢 V（−75% 移速）+ 三轴同系数的整体压速** —— 沿原路慢慢走，方向不变。
  - **弹射物**（箭矢、雪球、三叉戟…）：**关掉重力**，速度压到 `PROJECTILE_SLOW_SPEED`（0.12 格/刻），
    沿原方向慢慢飞 —— 不会因为重力越积越多而一头栽下来（早先横竖分开阻尼的那版就是这个毛病）。
    离开力场、或力场结束时重力还回去（`GRAVITY_HELD` 登记）。
  - **其它非生物实体**（掉落物、下落的方块、TNT…）：三轴同系数压速到 `OBJECT_DAMP`（50%）。
  - **己方一律跳过**（见下面的「己方后门」）：主人、同一主人的女仆/宠物、同队成员，
    以及他们射出的箭矢，都不受影响。
- **戴帽者自己固定获得抗性提升 II**（放大 1），四顶帽子都一样，蓄力全程挂着、
  **蓄力一结束立刻收掉**。这是给"站着挨十几秒打"的一点兜底：蓄力期不能打被动/中立生物、
  还要被围殴，没有减伤很难撑满一整轮。

> 抗性只加在**戴帽者本人**身上，不扩散到周围 —— 和时间差力场正好相反。
> 实现是每刻挂一个 10 刻的短时长效果，所以哪怕中途摘帽子/换帽子漏掉了显式清理，
> 它也会在半秒内自己掉干净；`clearChargeResistance` 只清放大恰为 1 的那一档，
> 玩家自己喝的抗性药水不受影响（跟清缓慢一个路子）。

> 相关常量在 `HatAbilities` 顶部：`SLOW_AMPLIFIER`、`LIVING_DAMP`、`PROJECTILE_SLOW_SPEED`、`OBJECT_DAMP`。
> 觉得怪物还是太死 → 调小这些压速系数或 `SLOW_AMPLIFIER`；觉得不够慢 → 反过来。

#### 己方后门（女仆戴帽子不能把主人一起按住）

技能是「对**任何**戴帽子的生物生效」的，所以车万女仆戴上帽子之后，那圈时间差力场会连主人一起压住 ——
实测就是这样，一眼就能看出来：女仆戴着帽子蓄力，你自己走不动。现在加了一道后门：

`HatAbilities.isFriendlyTo(wearer, entity)` 是唯一的「自己人」判据，命中任何一条就算己方：

| 判据 | 覆盖的情况 |
| --- | --- |
| **同一个主人** | 女仆戴帽 → 不减速主人；玩家戴帽 → 不减速自己名下的女仆/宠物 |
| **被戴帽者自己驯服的** | 同上，玩家没有主人，所以「玩家自己」被当成自己的主人 |
| **同一计分板队伍** | `Team.isAlliedTo`，组队玩的时候整队免疫 |

实现上走的是原版 `OwnableEntity#getOwnerUUID`（玩家单独当作自己的主人）：
**车万女仆的 `EntityMaid` 继承 `TamableAnimal`，而 `TamableAnimal` 就是 `OwnableEntity`**，
光辉「神隐」的队友判定（范围另算：直接取时间差力场那圈）、以及「掌控」内讧挑对手都走这一个函数 —— 所以被光柱「强控」
（`setNoAi`）的目标同样不会是自己人，队友和你的宠物永远不在点名之列（**友军豁免**）。

> 要放开某个目标（比如允许误伤宠物），改 `isFriendlyTo` 一个地方就行。
> 想让光柱也能打其他玩家，改 `isEnemy` 里那句 `entity instanceof Player`。

### ③ 蓄力结束

同一刻完成四件事：

1. 撤掉 5 格内的时间差力场 —— **周围生物的缓慢效果全部消失**。
2. 获得 **「迅捷 II」** —— 一直挂到本轮循环结束（下一轮蓄力开始时收掉）。
3. 播放信标激活音效作为提示。
4. 附魔「预知」（如果附了）在**这一刻**释放：30 格内的敌人定住，时长按等级取「本轮循环剩余长度」的 1/3、2/3、3/3（III 级打满全程）。

### ④ 持续照射（锁定最近的敌人）

不是「打一发」，而是**持续照射**，并且**自动锁定最近的敌人**：

- **锁定规则**：每刻在 24 格内取**最近的合法敌人**；出现更近的就立刻改锁那个
  （也就是会**转火**）。光柱从**胯部**（腿与身体的交界，`BEAM_ORIGIN_HEIGHT_RATIO = 0.4` 倍身高）
  出发、直接指向锁定的目标。
- **单体伤害**：一道光**只打它锁定的那一个**，射程 24 格。锥形范围内的其它敌人**不会**被顺带扫到
  —— 早先是"锥内所有敌人一起挨打"，一道光扫进人群会溅一片；现在一次只认一个目标，
  多道光（红帽「光柱」）就是各打各的那一个。
- 被照中的**敌人每刻（1/20 秒）受到一次伤害**，无视护甲。每刻伤害分成两部分：

  ```
  固定伤害：该帽子的 damagePerTick（**黑/白/红统一默认 10，「全」15**）—— 走正常的 hurt()
  附加伤害：目标当前生命值 × 5%           —— 直接 setHealth 改血，绕过一切减伤
  ```

  **伤害类型是本模组的自定义类型 `hatmod:flash`**（定义在
  `data/hatmod/damage_type/flash.json`，造成者记成戴帽者，所以击杀算他的）。用自定义类型而不是
  `minecraft:magic`，是因为原版和其它模组会给魔法伤害加抗性，自定义类型没有现成的防御手段。
  它同时还挂进了 `minecraft:bypasses_invulnerability` 标签，所以灾变那种「受击无敌帧 /
  单次伤害上限」也拦不住它。
  固定伤害走 `hurt()`，护甲、抗性、掉落、击杀归属、死亡信息全都正常；
  附加的那 5% 直接 `setHealth`，灾变 Boss 的伤害上限对它无效 —— 这就是**强制百分比伤害**。
  但 `setHealth` 只改血、不触发死亡，所以目标血量低于最大生命的 **5%** 之后就不再扣附加伤害，
  把收尾让给固定伤害走正常死亡流程（否则会卡在「0 血不死」，不掉落也没击杀）。
  1.20.1 没有 `bypasses_cooldown` 伤害标签，改为每刻清零 `invulnerableTime`，
  从而绕过原版 10 刻受击无敌帧。
- 被照中的敌人同时获得**缓慢 255**（amplifier 254）、速度归零，**完全动不了**。
- **其他生物戴帽子时，玩家也能看到它的光柱**（光柱对每个戴帽子的生物各画一条）。

> 光柱的指向由服务端决定并同步给客户端（只在**换目标时**发一条很小的包），
> 所以画面里光柱锁的人和实际挨打的人是同一个。

### 专属效果

- **黑帽 · 瞬移闪避**：蓄力期间只要受到任何伤害，就**瞬移躲开，这一击完全落空**。
  随机方式与末影人一致（±16 格、±8 格高、最多试 16 次），落点判定与末影珍珠同源
  （向下找可站立地面、检查碰撞与液体），但**不造成任何摔落伤害**。
  - **伤害被完全免疫**：不是"先挨一下再传送走"，而是**整个伤害事件被取消** ——
    不掉血、护甲不掉耐久、不吃击退，伤害附带的中毒/燃烧之类也一并作废，致死一击同样能躲开。
    实现上是先传送、传成功才 `setCanceled(true)`：找不到安全落点就照常挨打，
    不会出现"白免伤又没闪走"这种两不沾的情况。
  - **蓄力期最多躲 3 次**（`BLINKS_PER_CHARGE`），用完就只能硬吃。进入下一轮蓄力时次数重置。
  - **照射期另有附魔「残影」给的 1/2/3 次**，蓄力结束进入照射的那一瞬间补满；两段各数各的。
  - 屏幕提示会显示剩余次数：「新神已至 · 已瞬移躲开这一击（剩余 2 次）」。
  - **传送特效是一条完整的路径**：从起点到落点沿直线撒一串末影 `PORTAL` 粒子（不再只在两端各一团），
    音效音量与 BGM 等量（`BLINK_SOUND_VOLUME = 3.0`）。
- **红帽 · 力量 I**：照射期间自身持续获得力量 I。
- **红帽 · 绿心**：附魔「吸血」吸血、满血时溢出的治疗**原样（无损耗）**转成**绿心** —— 这是本模组
  自己的一个抗伤池（不是原版「吸收」换色）：**优先级比黄心还高**，受伤先扣绿心、
  扣完才轮到黄心与血量；**无限时长**（不挂状态、没有倒计时），但掉落速度随颗数指数增长、基础 1 秒/颗（2 点 = 一颗心）。
  数值只存在服务端，变一次推一次；血条上方那条**绿心能量条**是客户端自己画的
  （`client.GreenHeartRender`：条长按最大生命换算、正中间写着当前几颗心），
  所以**原版黄心不受影响、还是黄的**。
  - **绿心按「减伤之后」的伤害扣**（`HatAbilities.mitigate`）：一套铁甲把 10 点砍成 4 点，
    绿心就只掉 4 点而不是 10 点 —— 护甲 / 抗性提升 / 保护附魔同样让绿心更耐用。
  - **整击被绿心吃下时，护甲一点耐久都不掉**：绿心这一层在伤害事件里把这一击整个取消
    （`LivingHurtEvent` / `LivingIncomingDamageEvent` 都发生在原版 `hurtArmor` 之前），
    所以不掉血、不吃击退、不触发无敌帧，也不磨损护甲。
- **白帽 · 永久增益**：戴着就一直有**迅捷 I + 跳跃 I**（显示为无限时长 `**:**`），
  摘掉帽子即消失。附魔「疾行」每级把这两者抬一级，但**跳跃封顶在 II**。
  蓄力结束给的那份「迅捷 II」一直挂到本轮循环结束
  （两种都是迅捷，原版同一种效果取等级更高的那个，所以蓄力结束到循环结束之间就是 II）。
- **「全」· 三效合一**：同时具备上面的**瞬移闪避（黑）+ 永久迅捷/跳跃（白）+ 照射期力量 I（红）**。
  实现上 `HatType.Trait` 从「单个枚举」改成「可变参数数组」，`has(Trait)` 做成员判断，
  于是 `HatType.ALL` 一次挂三个特性、而三种效果的调用点（`onLivingHurt` 的闪避判定、
  `applyPermanentBuffs`、`tickingFlash` 的力量）都是原样复用，一行都没改。
- **四顶帽子通用 · 附魔护甲**：帽子上每多一个附魔，就给戴帽者多加 **2 点护甲**
  （`ARMOR_PER_ENCHANT`，含原版头盔附魔在内，按附魔个数算）；摘帽 / 换帽立刻收掉。

### 专属附魔（每顶帽子 3 个）

四顶帽子对**原版所有头盔附魔**都兼容（保护、爆炸保护、弹射物保护、火焰保护、水下呼吸、
水下速掘、荆棘、耐久、经验修补、绑定诅咒、消失诅咒……），走的是正常的
`EnchantmentCategory.ARMOR_HEAD` 通道。除此之外，黑 / 白 / 红每顶还各有 **3 个专属附魔**，
只有对应的那顶帽子能附上（注册名 `hatmod:<id>`，等级上限 III）：

> **「全」例外：它对全部 9 个专属附魔都开放。** 判定在
> `HatEnchants.Kind.accepts`（`candidate == 自己的帽子 || candidate == HatType.ALL`），
> 附魔台 / 铁砧走的是重写过的 `canEnchant` 与 `canApplyAtEnchantingTable`，所以「全」既能在附魔台
> 随机刷到这些附魔，也能用附魔书直接敲上去 —— 这是它最核心的价值。

> 三个「强化光柱」附魔（预知 / 光辉 / 光柱）早先**只是同一行加法**（每级 +1 伤害），
> 彼此毫无区别 —— 那样不如打成一本通用附魔书。现在它们**都不再加光柱伤害**，
> 各自换成一个只属于自己帽子的机制（光柱的每刻固定伤害一律是各帽子的 `damagePerTick`，默认 10）：
> **预知 → 定身静止**（**蓄力完成的那一刻**把 30 格内的敌人按原位定住，时长按等级取本轮循环剩余长度的 1/3、2/3、3/3（III 级打满全程），
> 走的是和蓄力时间差力场同一个 `applyStillness`；视野**整段变为黑白渲染**（持续黑白）；
> **光辉 → 神隐**（照射期间给戴帽者与**时间差力场圈内**的所有队友挂「神隐」——就是原版隐身，
> 模型照原版规矩消失，另加「定期把已经锁定自己的敌人甩开」，
> 范围直接取时间差力场（5 格起、还能被「缓速」撑大），时长按等级 6/8/10 秒；
> **监守者也在保护名单里**：它的嗅觉不吃隐身、目标又存在 Brain 记忆里，所以对它单独每刻抹一次目标与怒气（见 `HatAbilities.blindWardenTo`）；
> **光柱 → 多道光柱 + 堆叠**（每级多 **1 道**，I/II/III 级最多 2/3/4 道；敌人够多就**一人一道**，敌人不足时多余的**堆叠**到最近的敌人身上、同一目标每多叠一道按 `BEAM_STACK_FACTOR`（0.4）**边际递减** —— 4 道全堆一个人合计约 **1.62 倍**而不是 4 倍），
> **吸血 → 吸血 + 绿心**（`LivingEntity.heal` 按光柱实际造成的伤害比例回血（每级 +5%），满血时溢出部分**原样（无损耗）**转成绿心（本模组自己的抗伤池，**优先级高过黄心**：受伤先扣绿心、扣完才轮到黄心与血量；无限时长、掉落速度随颗数指数增长、基础 1 秒/颗），
> **不设上限** —— 现在整合包里限伤满天飞、玩家血量也能堆到几千，封顶反而让吸血变鸡肋）。
> 三个新效果都只在照射阶段生效、且都挂在对应帽子上，所以互相不冲突。
>
> 红帽的定位就是**唯一一顶把附魔全点在伤害上的帽子**：黑是预知（闪避 + 静止）、
> 白是速度与支援（永久迅捷 + 神隐）、红是输出 —— 但**一本附魔只干一件事**：
> 「光柱」专心加光柱（每级 +1，满级 4 道），「吸血」专心给续航（吸血 + 绿心）。
> 原先一本「光柱」同时给输出和生存，怎么调都超模，所以拆成了两本。
>
> 红帽因此是个**狂战士**：光柱能**吃力量/虚弱**、还能**多道堆叠**（敌人越多打面越广，单挑一个 Boss 就 4 道全堆上去），
> 代价是没有黑帽的**闪避与静止**、也没有白帽的**速度与辅助** —— 三顶原色帽的定位：**黑 = 生存闪避、白 = 速度辅助、红 = 狂战士输出**。
> **「全」= 三顶合一**：三种专属效果与 9 个专属附魔全收进一顶，自带光效。它每轮**随机取一条路线**
> （黑/白/红，随机不重复），本轮就完全是那顶帽子的手感 —— 时长、BGM、帧伤（黑 12/白 10/红 15）、
> 力场粒子颜色，连**身上帽子的颜色**都跟着变，一眼看出这轮在走哪条。三种专属特性**不跟路线走、
> 始终同时生效**；附魔效果三条路线都吃得到。见 {@code HatRouteState} 与 {@code HatAbilities.nextRoute}。
>
> 「神隐」**本身就是隐身**：服务端直接把这只生物的「隐身」标记置上（原版隐身效果内部也只是置这个标记），
> 渲染完全走原版那一套 —— 模型消失，护甲 / 手持物照旧可见（原版隐身的规矩就是这样）。
> 状态栏上只有「神隐」这一条，不会平白多出一条「隐身」，也不会因为多挂一份效果而闪。
> 时长是**明确写出来**的：剩余不足 2 秒（`VEIL_REFRESH_MARGIN`）时补足 6/8/10 秒（封顶 10 秒），
> 配合照射期间一直在补，照完还会再持续那么久 —— 玩家能一眼读出还剩多久。
>
> 比原版多做的一件事是**索敌**：隐身骗不过「已经锁定你」的敌人（走得越近越明显），
> 所以挂着神隐的生物每 10 刻把 32 格内锁着自己的目标甩掉一次，监守者则每刻单独抹掉它的目标与怒气
> （见 `HatAbilities.blindWardenTo`）。**自定义的轮廓 / 藏护甲那套渲染已经撤掉了**，
> 不再需要任何附加的网络包。
>
> 光柱每刻的总伤害 = 当前生命 × 5%（`healthDamageRatio`，可在调参器里改）+ 每刻固定伤害
> （`HatType.damagePerTick`，默认 10；**不吃任何附魔加成**），**再整体乘一个「力量倍率」**。
> 这个倍率来自戴帽者身上和伤害相关的状态效果 —— 原版力量只加 `ATTACK_DAMAGE`、只有近战算得进去，
> 光柱是直接 `hurt()` 一个固定值、默认完全吃不到，所以这里手动折算：
> **力量每级 +35%（力量 I = ×1.35）、虚弱每级 −20%**（`STRENGTH_BEAM_BONUS_PER_LEVEL` /
> `WEAKNESS_BEAM_PENALTY_PER_LEVEL`，倍率夹在 0.1×–4×）。**固定伤害和百分比伤害一起吃这个倍率**，
> 所以红帽自带的「照射期力量 I」等于白送光柱 +35%；想再接别的模组的易伤，往 `beamPowerMultiplier` 里加一行即可。
> **多道光柱堆叠**在同一目标上时，每道再乘自己的堆叠系数（`BEAM_STACK_FACTOR`）—— 两处相乘才是红帽单挑的最终倍率。
>
> 「掌控」**不改蓄力时长**（改了会打断音乐的节奏），而是在蓄力开始后的第 15 秒插一脚：
> 让最近的敌人失去索敌目标 5 秒（每级 +5 秒，III 级 15 秒），目标是 I/II/III = 5/10/15 人，
> 并给它们挂上光灵标记 —— **标记持续多久跟失去索敌一样长**（控 15 秒就亮 15 秒）。
> **监守者也照控不误**：清 `Mob#target` 对它没有用（它的目标在 Brain 记忆里），所以另走一条路每刻连怒气一起抹（见 `HatAbilities.blindLockedWarden`）。
> 标记的颜色是**粉色**：原版发光描边的颜色只能取自实体所在的**计分板队伍**颜色
> （没有队伍就是白色，光灵箭给的就是那个白框），所以这里把目标临时编进一个叫
> `hatmod_dominion` 的粉色队伍（`ChatFormatting.LIGHT_PURPLE`，即 #FF55FF），
> 时间一到就退队、它原本的队伍再还回去。不需要 mixin，也不碰客户端渲染。
> 唯一的副作用：被控的生物之间算同队（不会互相寻仇），带名牌时名字会被染成同色。
> 发动的那一瞬间，戴帽者**眼部会闪出一小团亮光**（原版烟花的白色 `FLASH` 粒子 + 一圈
> `END_ROD`）—— **纯表现**，不参与任何判定，只是让这一下「看得见」。位置取眼睛、
> 略微前挪一点，免得第一人称下正好压在近裁剪面上自己反而看不到。
> 「失去索敌」是用 `LivingChangeTargetEvent` 实现的 —— 持续期间它每次想重新锁定都会被取消，
> 所以不会出现「清空一次目标、下一刻又锁回来」的情况。
> **这里是取消事件，不是把新目标置空**（`HatAbilities.blockTargeting`）——
> 置空会踩一个致命坑：走 Brain 的生物（女仆/猪灵/监守者）索敌走 `StartAttacking`，
> 它把 `getNewTarget()` 原样丢进 `Optional.of(...)`，null 进去就当场 NPE 崩服。
> 具体见下面「1.20.1 专属坑：置空目标会崩服」。
> 另外也不是无脑取消：`Mob#setTarget(null)`（清目标）自己也走这个事件，
> 所以只在「Brain 抢目标」或「锁非空目标」时取消，置空一律放行。
> 「缓速」加的是**加和清两个方向共用**的半径（`HatAbilities.slowRadius`）——
> 只加一边的话，附魔撑大的那一圈会留下清不掉的「缓慢」。

实现方式：`HatEnchants` 用 `DeferredRegister<Enchantment>` 注册 9 个 `HatEnchantment`，
每个重写 `canEnchant(ItemStack)` **和** `canApplyAtEnchantingTable(ItemStack)` 只认自己那顶帽子。
两个都要重写的原因：附魔台的候选池走的是 `canApplyAtEnchantingTable`
（`EnchantmentHelper.getAvailableEnchantmentResults`），**不是** `canEnchant` ——
只重写后者的话，专属附魔会在附魔台上出现在另外两顶帽子的候选里。铁砧与附魔书走 `canEnchant`。
附魔之力需求和原版头盔附魔同级（1 级 10 点起，每级 +10，最高 50 + 每级 10），
稀有度 `RARE`（候选权重 2）。

**和原版附魔同等地位**（能上附魔台、能出在宝箱的附魔书里、能跟村民换到）：1.20.1 里这三个
判定分别是 `isDiscoverable()`、`EnchantRandomlyFunction` 的筛选、`isTradeable()`，
原版实现**默认全部为 true**，所以什么都不用加就自动成立。有两点值得记下来，免得以后误改：

- 宝箱那条路（`EnchantRandomlyFunction`）在物品是书时会**绕过** `canEnchant` 直接放行
  （`lambda$run$0`：`if (isBook) return true`），所以"只认帽子"的 `canEnchant` 不会把
  附魔书从战利品表里挡掉。
- 村民交易（`VillagerTrades$EnchantBookForEmeralds`）只筛 `isTradeable()`，
  同样不碰 `canEnchant`/`canApplyAtEnchantingTable`。

> 顺手补的两处兼容：`HatItems` 显式重写了 `isEnchantable`（按原版判定本来就该是
> true，写死是为了以后改材质/属性时不会莫名其妙失效），并加了
> `data/forge/tags/items/armors/helmets.json` 把四顶帽子并进 `forge:armors/helmets`，
> 让认标签的模组也把它们当头盔看。
>
> 「全」还额外重写了 `Item#isFoil` 恒返回 true —— 不附魔也自带附魔光效，
> 一眼就能从物品栏里认出这顶传说的帽子（另外三顶照原版规矩：有附魔才有光效）。

## 耐久规则（`HatDurability.java`）

四顶帽子走一套自定义的耐久玩法，都集中在 `HatDurability` 的常量里：

| 规则 | 数值 | 实现 |
| --- | --- | --- |
| 基础耐久 | **300** | `HatItems` 的 `Item.Properties().durability(...)`（1.20.1 还要同步 `getDurabilityForType`） |
| 限伤 | **3 秒内最多磨损 1 点** | 重写 `Item#damageItem`（`ItemStack.hurtAndBreak` 的必经之路），距上次扣减不足 60 刻就返回 0 |
| 修复 | **1 个皮革修 20 点** | 监听 `AnvilUpdateEvent` 自己算，**绕开**原版「每个材料修最大耐久的 1/4」 |

几个要点：

- **限伤的状态存在物品自己的 NBT 里**（键 `hatmod_last_drain`，存的是"上次是哪一刻扣的"）。
  不放进任何全局表 —— 多人、多顶帽子、进存档重登都不会串。
  1.20.1 用 `ItemStack.getOrCreateTag()`，1.21 用 `DataComponents.CUSTOM_DATA`。
- **为什么不用原版的铁砧修复公式**：原版是「每个材料修最大耐久的 1/4」。耐久 300 的帽子
  一个皮革就修 75 点，等于三个皮革满血，太廉价了。所以要自己接管。
- **接管铁砧分支的副作用是"改名"也会一起被接管** —— 原版那条分支被跳过之后，
  名字就不会自动应用了。所以 `onAnvilUpdate` 里要自己把名字应用到输出上，
  语义照抄原版 `AnvilMenu#createResult`（名字和当前显示名相同则不动，否则设置自定义名；
  空白则清掉）—— 少了"相同则不动"这一条，玩家什么都没改也会被固化成自定义名。
- **限伤只认护甲那条路**：`damageItem` 是 `ItemStack.hurtAndBreak` 的必经钩子，
  玩家的护甲耐久走的就是它（`Player#hurtArmor` → `doHurtEquipment` → `hurtAndBreak`）。

## 光柱是怎么画出来的（重要）

光柱**不是粒子**，而是一根从**胯部**（腿与身体的交界）照出去的**锥形体积光**
（几何体直接画出来，和凋灵风暴牵引光束同一思路）。

- 服务端只管逻辑与伤害。「**正在照射**」和「**锁定了谁**」由同一个网络包同步给客户端
  （`HatNetwork` 的 `(wearerId, targetId, beaming)`），只在状态变化时才发一条很小的包。
- 客户端在 `RenderLevelStageEvent` 的 `AFTER_PARTICLES` 阶段，遍历当前维度里**所有**
  带了这个标记的生物，用 `VertexConsumer` 以 QUADS 模式各画一组**同轴圆台壳**
  （锥面，只有侧面、没有端盖），方向对齐光柱指向。

> **不要用状态效果来判断「正在照射」**（踩过坑）。1.20.1 的原版只会把**生物**的状态效果
> 同步给它的**乘客** —— 只有 `ServerPlayer` 重写了那段逻辑、会额外发给自己一份。
> 所以「玩家自己射出的光柱看得见，女仆/其它生物射出的完全看不到」正是这个原因：
> 效果压根没发到客户端。1.21.1 改成了走实体追踪器同步，所以那边从没这个毛病。
> 现在两版统一改用本模组自己的包（`PacketDistributor.TRACKING_ENTITY_AND_SELF`），
> 玩家和生物走同一条路径。以前还挂着一个不可见的 `hatmod:beam` 标记效果做同步，
> 现在客户端完全走自己的包、不再读它，那个空壳效果已经**整个删掉**了。
- **起点在胯部，不在眼睛** —— 这是**第一人称能不能看见光柱的关键**。
  相机正好坐在锥体轴线上时，锥壳的投影会缩成一圈**空心**的环（正中间是空的），
  所以第一人称几乎什么都看不到（第二/第三人称从侧面看却很清楚，就是这个原因）。
  起点下移到胯部（`HatAbilities.BEAM_ORIGIN_HEIGHT_RATIO = 0.4` 倍身高，玩家约 0.72 格高）之后，
  相机在轴线**上方**约 0.9 格，看到的是锥体侧面，第一人称立刻就有明显的光柱了。
  命中判定（`insideCone`）、粒子、渲染三处共用 `HatAbilities.beamOrigin`，画面和判定永远一致。
- **体积感是一层层叠出来的**：`CONE_LAYERS` 层圆台共用同一个灯口半径（0.16 格），
  末端半径从 1/8 倍一路递增到 1 倍（最外层 3.4 格，约 8° 半角）。加色混合下这几层互相叠加，
  轴向最亮、向外渐弱 —— 看着才是一团**体积光**，而不是一张薄壳。
- **亮度沿长度递减**：灯口最亮，到末端只剩 `TIP_BRIGHTNESS_SCALE`（0.18）。
  这是「手电筒」的关键。早先那版反过来（末端最亮、最不透明），
  于是整根光锥看着像喷出去的一团雾 —— 那是观感崩掉的主因。
- 贴图 `beam.png` 沿**圆周方向恒定**、沿光柱方向一圈圈明暗，纵向滚动出「能量在流」的纹路。
  圆周方向必须恒定：早先那版贴图两侧是透明的，绕着锥面铺一圈会出现一道透明接缝，
  看着像一圈旋转的雾。
- 再沿轴线撒一串正对相机的亮片（`beam_core.png`）：锥壳是「只有面、没有体积」的曲面，
  顺着它的轴线看过去投影会缩成一圈很窄的环、正中反而空着，靠这层补上实心的亮芯。
- 第一人称下光锥顶点会沿视线**前移 0.5 格**：起点虽然在胯部、相机已经在轴线外，
  但往前挪一点可以避免锥体近端插进自己的身体里。其他生物不需要这个偏移。
- 粒子仅作点缀（光柱周围零星火花 + 灯口爆点），主体全部来自几何体。
- 光柱颜色按帽子微调（`BeamRenderer.beamTint`）：白 = 纯白、黑 = 偏一点冷紫、红 = 偏一点暖橙。
  系数只在 ±10% 上下，远看还是一束白光，只为让人一眼认出这是哪顶帽子打出来的。
- 蓄力时时间差力场边缘还有一圈细碎粒子（`HatAbilities.spawnSlowRing`）：半径**直接取力场半径**，
  所以附魔「缓速」把力场撑大时它跟着一起变大；颜色按帽子分 —— 黑 = 幽匿魂（暗青）、
  白 = 末地烛（白）、红 = 绯红孢子（暗红），用的都是原版粒子，没有额外注册粒子类型。

相关文件：`client/BeamRenderer.java`（几何与绘制）、`client/BeamRenderTypes.java`（光柱 RenderType）、
`assets/hatmod/textures/particle/beam.png`（光柱贴图）。

### 1.20.1 上的坑：开光影时光柱不显示（已处理）

**现象**：1.20.1 里光柱完全不显示，日志里没有任何报错；同一份代码在 1.21.1 上正常。

**原因**：这个整合包用的是 **Oculus**（光影）。光影模组是按「渲染类型」接管绘制的，它只认识
原版那一批；自己 `RenderType.create` 出来的类型（早期叫 `hatmod_beam`）在开光影时不会被画出来，
表现就是光柱凭空消失。

**修法**：改用**原版**渲染类型，不自己造。这里用 `RenderType.energySwirl(贴图, 0, 0)`
（僵尸围城那道「能量漩涡」用的类型），它是原版那批里唯一同时满足三条的：
**加色混合**（光必须靠叠加变亮）、**不剔除背面**（第一人称时人是站在光锥内部的）、
**只写颜色不写深度**（自身各层不互相遮挡、但会被墙挡住）。

> 另一个原版加色类型 `RenderType.eyes` 不能用：它剔背面，而且着色器里带着
> `if (color.a < 0.1) discard;`，会把柔和的外缘切出硬边。
> `energy_swirl` 也有这句 discard，所以**顶点的透明度必须给满 1.0、亮度只能写在颜色里**
> （加色混合是 `ONE,ONE`，透明度本来也不参与叠加）。要是用 alpha 在贴图里画形状，
> 大半个光锥会被这句 discard 整片裁掉 —— 两个光柱贴图因此都把形状画在 RGB 上、alpha 一律 255。

> 注意 `RenderType.energySwirl(...)` **每次调用都会新建一个对象**，而 `BufferSource` 是拿对象身份
> 当 key 的。必须缓存成静态实例，否则「画」和 `endBatch` 时拿到的不是同一个实例，缓冲永远刷不出去。

1.21.1 那份也用同一个原版类型：两个版本走完全一样的渲染路径，不至于换个光影包又踩同一个坑。

> **顶点属性一个都不能少。** `energy_swirl` 的顶点格式是 `NEW_ENTITY`：
> 位置 → 颜色 → 贴图(UV0) → overlay(UV1) → 亮度(UV2) → **法线**。
> 写顶点时每个属性只在「正轮到它」的那一刻才被写入、顺序不能乱；少写一个顶点就收不了尾，
> `BufferBuilder` 和 Embeddium(Sodium) 的 `SodiumBufferBuilder` 都会在 `endVertex()` 抛
> `Not filled all elements of the vertex` 直接崩游戏（改用信标光束那版就是因为漏了法线崩过一次）。

**顺带修掉的崩服**：`hatmod:flash` 是模组自带数据包提供的。一旦这个数据包没被注册，
原来的代码用 `getHolderOrThrow()` 去查，会直接抛 `IllegalStateException`，
顺着「玩家的 tick」把服务端整个崩掉（日志里能看到 `Missing data pack mod:hatmod`）。
现在改成：查不到就回退到原版 `minecraft:generic_kill`（它自带
`bypasses_armor / bypasses_invulnerability / bypasses_resistance`，「无视减伤」这个性质一致），
并且**服务端启动时会为每顶帽子打一行日志**说明配置的伤害类型到底有没有就绪 ——
下次不用再靠崩服来判断是不是数据包的问题。

## 调参器（创造模式物品）

创造模式物品栏「战斗」里多了一个 **神的调参器**（`hatmod:tuner`，**没有合成表**，只能创造模式拿）。
右键打开界面，逐顶帽子调这些：

| 字段 | 含义 |
| --- | --- |
| 帽子 | 上面四个按钮切换黑 / 白 / 红 / 全，四顶各自独立一套参数 |
| 蓄力刻数 | 进入光柱前的蓄力时长（20 刻 = 1 秒） |
| 照射刻数 | 光柱持续多久（这就是「发射光束的时间」） |
| 每刻固定伤害 | 走正常 `hurt()` 的那部分，每刻结算一次 |
| 附加百分比 | 直接 `setHealth` 扣掉「当前生命 × 该比例」 |
| 百分比下限 | 目标血量低于「最大生命 × 该比例」后不再扣附加伤害 |
| 伤害类型 id | 光柱用哪种伤害类型，默认 `hatmod:flash`；可填任何已注册的，例如 `minecraft:magic` |
| 自己的 BGM 优先 | 右上角开关（开 / 关），默认**开**：见上面「音乐」一节。跟参数一起保存、一起落盘 |

### 「全帽」页：路线专用的一组调试项

选中「**全**」时，界面切换成**路线调试**布局（这是它和三顶原色帽唯一的界面差异）：

| 字段 | 含义 |
| --- | --- |
| 黑 / 白 / 红路线帧伤 | 「全」轮到这条路线时的**每刻固定伤害**（出厂 12 / 10 / 15）。前三个框改成这三个值 |
| 蓄力刻数 / 照射刻数 | **禁用（灰掉）**：这两个由本轮路线决定，不可在这里改 |
| 附加百分比 / 百分比下限 / 伤害类型 | 仍是「全」自己那一份配置（9 个附魔都吃得到，与路线无关） |
| 强制路线 | 单独的循环按钮（**随机 → 黑 → 白 → 红**）。默认 **随机**＝正常玩法；选某条颜色后，「全」**每轮都固定走那一条**，方便逐条核对时长 / BGM / 粒子颜色 / 帽子渲染颜色（不然要等随机轮到） |

> 「全」的路线帧伤、强制路线跟其它参数一样**一起保存、一起落盘**到 `config/hatmod.json`
> （字段 `routeDamageBlack/White/Red` 与 `forcedRoute`）。这两个字段带出厂默认值，
> 所以**老配置文件不需要删除**它们会自动补齐；也正因此**没有为它们提高 `CONFIG_VERSION`**，
> 不会把已经调好的时长/伤害冲掉。

点「保存」把当前这顶帽子的值发给服务端；服务端夹一遍范围、写进 `config/hatmod.json`、
再把最新的一份广播给所有人 —— **改完立刻生效，不用重启**。

- **服务端权威**：真正生效的是服务端那一份；客户端只收一份只读副本，用来把界面上的当前值显示出来。
- **保存后界面立刻回显**：点「保存」会同时把这份值写回客户端副本，所以关掉再打开看到的就是刚填的值，
  不用等服务端回包；服务端改完广播回来会覆盖成「夹过范围的最终值」，被拒时也会自己纠回真实值。
- **权限**：只有创造模式玩家或 OP 能改；其他人按保存会被拒绝（聊天栏提示）。
- **恢复默认**只是把界面上的框填回出厂值，还是要按「保存」才真的生效。
- 直接手改 `config/hatmod.json` 也可以。读取时会把取值夹到合法范围
  （时长 0–72000 刻、伤害 0–100000、百分比 0–1）；伤害类型 id 填坏了只会回退到
  `minecraft:generic_kill` 并在日志里警告，**不会崩**。手改完不想重启游戏可以用 `/hatmod reload`。

### 保存没生效？先看日志，再用命令兜底

「点了保存，数值还是原来的」这种情况，现在**每一步都会在日志里留一行**（默认 INFO，`logs/latest.log`）：

| 日志行 | 说明 |
| --- | --- |
| `[HatMod] 发出调参请求：…` | 客户端确实点到了「保存」（按钮回调跑了）。**没有这一行 = 按钮没点到** |
| `[HatMod] … 参数已更新：…` | 服务端收到了包并且通过了权限检查 |
| `[HatMod] … 既不是创造模式也没有 OP 权限，已拒绝调参请求` | 服务端收到了包，但权限不够 |
| `[HatMod] 收到调参请求但拿不到发送者，已忽略` | 包到了但发送者丢了（异常情况） |
| `[HatMod] 参数已写入 …\config\hatmod.json` | 落盘成功；同一目录下能看到 `hatmod.json` |

> 另外，数值框做了**全角转半角**：中文输入法下很容易把 `100` 打成全角的 `１００`，
> `Integer.parseInt` 会直接抛异常，表现出来就是「点了保存什么都没发生」。
> 现在全角数字、全角句点、全角冒号都会被自动转成半角（半角输入不受影响）。
> 真的填错了（比如留空、填了字母）会在聊天栏红字提示，不会静默失败。

**兜底路径：`/hatmod` 命令。** 界面走的是本模组自己的网络包，命令走原版命令通道
（`ServerboundChatCommandPacket`），任何整合包里都不会被挡；两边改的是同一份
`HatSettings`、落盘到同一个文件。所以万一自定义网络包在某个整合包里失灵，命令照样能调：

```
/hatmod                                             # 列出四顶帽子当前的参数 + 「全」的路线帧伤 / 强制路线
/hatmod tune <hat> <蓄力> <照射> <固定伤害> <附加%> <下限%> [伤害类型]
/hatmod tune black 100 200 20 0.05 0.05             # 黑帽：蓄力 100t、照射 200t、每刻 20、附加 5%、下限 5%
/hatmod tune red 588 152 3 0.05 0.05 minecraft:magic
/hatmod reset <hat>                                 # 恢复出厂值
/hatmod route                                       # 查看「全」当前强制路线
/hatmod route black                                 # 「全」每轮固定走黑路线（random = 恢复随机）
/hatmod routedamage                                 # 查看「全」三条路线帧伤
/hatmod routedamage 12 10 15                        # 设置「全」黑/白/红三条路线的帧伤
/hatmod reload                                      # 丢掉内存里那份，重新读 config/hatmod.json
```

`<hat>` 写 `black` / `white` / `red` / `all` 或带 `_hat` 的完整名都行；权限等级 2（创造模式房主 / OP）。

## 关于"戴上帽子就崩"的修复（1.20.1）

**现象**：1.20.1 里一戴上帽子游戏立刻崩，报
`NoClassDefFoundError: com/hatmod/HatAbilities$State`。

**原因**：不是帽子本身的问题，而是和 **AllTheLeaks**（内存优化模组，处理 FML#10684）
冲突。它会在加载完成后强制关闭各个 mod jar 的文件系统句柄；之后再**第一次**用到某个类时，
类加载器已经读不到 jar 了，于是抛 `NoClassDefFoundError`。
原来的 `State` 是 `HatAbilities` 的内部类，只有在第一次戴帽子时才会被加载 ——
正好撞在这个时间点之后，所以"一戴就崩"。

**修复**（三处，都在 `HatState.java` / `HatPreloader.java` / `HatMod.java`）：

1. `State` 提成独立的顶层类 `HatState`。
2. 新增 `HatPreloader`：在 mod 构造阶段（jar 还开着）用 `Class.forName` 把本模组
   所有类预先登记进类加载器，之后就不再依赖 jar 句柄。客户端专属的类由
   `client/HatModClient` 的静态块负责（那个类只在客户端加载）。
3. mod 构造函数里调用 `HatPreloader.preloadCommon()`。

> **新增类时记得补 `HatPreloader` 的名单。** 匿名内部类、私有内部类同样要单独列出来 ——
> 它们不是跟着外层类一起加载的。漏掉的话不会立刻报错，而是在"第一次用到它"的那一刻才炸，
> 而且往往发生在游戏进行中。目前漏过的两个已经补上：
> `HatAbilities$Hold`（第一次用 `hold()` 强控怪物时加载）和
> `HatSettings$1`（`FILE_TYPE` 那个匿名 `TypeToken`，第一次用到 `HatSettings` 时加载）。
> 想自查：把 jar 里 `com/hatmod/**.class` 列出来和名单比一遍，应该一个不差。

### 同一个坑的另一半：护甲贴图（「戴着白帽贴图变成紫黑错乱」）

**现象**：戴上某一顶帽子时，帽子的**护甲贴图**不是那顶帽子的颜色，而是原版那种
紫黑「缺失贴图」的错乱格子。

**原因**：和上面是**同一个 jar 句柄问题**，只是受害者从「类」换成了「贴图」。
护甲贴图是**独立贴图**（不参与图集拼接），走 `TextureManager.getTexture(...)` 的
**按需加载** —— 第一次有人戴帽子时它才去读 jar。而原版一旦加载失败就把结果缓存下来、
**不再重试**：读不到一次，那顶帽子整局都是错乱贴图，怎么摘怎么戴都不会自己好。
（黑 / 白 / 红三张贴图本身没问题：三张的像素掩码逐格一致、只是颜色不同，
所以"只有白帽错乱"从来不是资源文件的锅，而是"谁第一个被加载谁中招"。）

**修复**：`client/HatTexturePreloader` —— 在**每次资源重载之后**（那一刻所有资源包都确定开着）
用 `getTexture` 把三张护甲贴图点一遍。之后渲染就只是查缓存，不再碰 jar。
时机和 `HatPreloader` 提前加载类完全对应：一个管类、一个管贴图。

> 顺带一提：换维度、换资源包、`F3+T` 都会触发资源重载，所以这个监听器每次都会重新执行，
> 不会出现"第一次好了、重载之后又坏掉"。加新帽子（新材质）时记得把它的贴图也加进
> `HatTexturePreloader.ARMOR_TEXTURES`。

> **每道光各锁一个、且只打它锁的那一个**（单体伤害），敌人不够就少发几道
> （单挑一个 Boss 时只发一道，不会叠在一起刷伤害）；
> `fanDirection(aim, i, count)` 把每道光的瞄准方向按 `BEAM_SPREAD_DEGREES`（6°）绕垂直轴散开，
> 服务端绘制和客户端绘制**调用同一个函数**，两边永远一致 —— 这个散角现在**纯属观感**
> （看得出是"几道"而不是一束），伤害直接打在各自锁定的目标上，不依赖锥形判定。

> `/data merge {NoAI:1}` 的效果，不选目标、不施法、不移动。灾变那种"边被控边丢技能"的 boss
> 之所以控不住，就是因为它们的技能挂在 AI 上、不吃缓慢；关掉 AI 才是真正的控住。
> 同时被控者打出的伤害也会被 `isAttackLocked()` 全部取消（这里的 `isAttackLocked` 现在只表示「被光柱强控」）。
>
> 强控用「最后一次被照到的刻」判定，**停照 2 刻后自动恢复 AI**（`releaseStaleHolds`，
> 由 `onServerTick` 每刻扫一遍）——所以施法者死亡 / 摘帽 / 掉线 / 走远都不会留下
> 一只永久 noAI 的怪。本来就没开 AI 的生物不会被记进 `forcedNoAi`，解除时也不会误开。

> 觉得怪物还是太死 → 把 `SLOW_AMPLIFIER` 调小（如 `2` = 缓慢 III）或把 `LIVING_DAMP` / `OBJECT_DAMP` 调大。
> 觉得不够慢 → 反过来；想让箭矢更慢地飞 / 更早停住 → 调 `PROJECTILE_SLOW_SPEED`。

### 音乐 —— `HatSounds.java` / `assets/hatmod/sounds.json`

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 曲子文件 | `assets/hatmod/sounds/music_{black,white,red}.ogg` | 单声道 Vorbis；**必须单声道**，否则不会有 3D 距离衰减 |
| 播放音量 | `HatMusic.MUSIC_VOLUME` = `3.0` | 客户端响度会被 clamp 到 1，所以不会更吵；它同时参与客户端的线性衰减计算（`max(volume,1) × attenuation_distance`） |
| 听见半径 | `HatMusic.HEAR_RADIUS` = `48.0` | 服务端按这个半径决定把「谁的 BGM 开始了」通知给谁；客户端也用它判断哪条还在可听范围内 |
| 衰减距离 | `sounds.json` 的 `attenuation_distance` = `16` | 客户端线性衰减到 `max(volume,1) × 16 = 48` 格处归零 |
| 播放时机 | `HatAbilities.startCharge()` | 每次进入蓄力（= 每次循环开始）通知客户端开播；「全」播的是**本轮路线**那首 |
| 停止时机 | `HatAbilities` 里 `HatMusic.stop(...)` | 摘帽 / 死亡 / 换帽 / 没有目标时通知客户端停播 |
| 谁来决定听哪条 | `client/HatMusicPlayer.java` | 「自己的 BGM 优先」开关打开时按听者取舍；关闭时全部照播 |

> 想让音乐传得更远：同时改 `HEAR_RADIUS`、`MUSIC_VOLUME` 与 `attenuation_distance` 三个数即可
> （服务端通知半径、客户端响度、衰减归零点要一致才自然）。

### 光柱外形 —— `client/BeamRenderer.java` 顶部

光柱本体是 **`CONE_LAYERS` 层同轴圆台壳**叠出来的：每层灯口半径相同、末端半径不同，
每层只画侧面（没有端盖），顶点写在 `drawFrustum(...)` 里。

| 常量 | 默认值 | 含义 |
| --- | --- | --- |
| `RANGE` | `24.0` | 光柱长度（格），同时也是伤害范围 `HatAbilities.FLASH_RANGE` |
| `CONE_LAYERS` | `8` | 圆台层数。层数越多、径向明暗过渡越平滑；层数少会看出"一圈一圈"的台阶 |
| `LENS_RADIUS` | `0.16` | 灯口（近端）半宽（格）。所有层共用 |
| `END_RADIUS` | `3.4` | **最外层**在末端的半宽（格）＝ 散射范围。3.4/24 ≈ 8° 半角，就是"手电筒张角"。**决定漏斗多胖** |
| `LAYER_BRIGHTNESS` | `0.075` | 单层灯口亮度。加色混合下八层叠起来轴向约到 1.0（刚好过曝成白芯）；想让光锥更亮就调它 |
| `OUTER_BRIGHTNESS_SCALE` | `0.62` | 最外层相对最内层的亮度。调小 → 外缘更柔、光锥更"芯亮边淡" |
| `TIP_BRIGHTNESS_SCALE` | `0.18` | 末端残余亮度。**这是"手电筒"的灵魂**：灯口最亮、越远越淡。调到接近 1 会立刻变回"喷雾" |
| `V_SCALE` | `0.075` | 贴图沿光柱方向的重复密度 |
| `V_SCROLL` | `0.22` | 贴图沿光柱方向的滚动速度 |
| `FIRST_PERSON_FORWARD` | `0.5` | 第一人称下把光锥顶点往前推的距离。起点已经在胯部、相机已在轴线外，这里只是避免锥体近端插进自己身体 |
| `CORE_START` / `CORE_STEP` / `CORE_HALF` / `CORE_BRIGHTNESS` | `0.5` / `0.35` / `0.22` / `0.18` | 沿轴线正对相机的亮片，用来补上顺着轴线看时中间那个空洞 |

> 想更"手电筒"一点：把 `END_RADIUS` 调小（光锥更窄更聚）或把 `TIP_BRIGHTNESS_SCALE` 调小（末端更暗）。
> 想更"爆发"一点：`END_RADIUS` 调大、`LAYER_BRIGHTNESS` 调大。
> 唯一不能做的是把 `TIP_BRIGHTNESS_SCALE` 往 1 调 —— 那就是当初"喷雾"的成因。

> 粒子只负责点缀：`HatAbilities.spawnBeamSparks()` 里火花按 12° 细锥撒、最近离起点 5 格。
> 早先按 35° 的大锥角从 1 格铺满，第一人称会满屏光点、把几何光柱压得看不见。

轴线上的那串**正对相机的亮片**（`drawCore`，贴图 `beam_core.png`）是补中间空洞用的：
圆台壳是"只有面、没有体积"的曲面，顺着它的轴线看过去投射成一圈很窄的环、正中反而空着。
起点下移到胯部之后相机已经不在轴线上了，但贴片仍然有用 —— 从侧面看光锥接近侧视时，
它就是那条实心的亮芯。可调：`CORE_START` / `CORE_STEP`（采样密度）、`CORE_HALF`（半径）、
`CORE_BRIGHTNESS`（单片亮度，加色会互相叠加）。

> **1.20.1 专属坑：「一串圆球」（已修）**
>
> 症状：1.20.1 里发射光柱时，沿光柱方向能看到**一串圆形光球**，从任何角度看都是圆的。
>
> 原因有两层，缺一不可：
> 1. 1.20.1 原版的 `energy_swirl` 着色器 JSON 里带一段 `"blend"`（普通 alpha 混合），
>    `ShaderInstance.apply()` 会在绘制时把它推给 GL，于是这个贴图实际走的是 **alpha 混合**，
>    **alpha 通道说了算**。而旧版 `beam_core.png` 的 alpha **整张都是 255**（形状只画在 RGB 上），
>    所以在 alpha 混合下每个亮片都是一块**不透明黑边圆盘** —— 轮廓清清楚楚。
> 2. 采样间距 `CORE_STEP = 0.35` 和亮片直径（`CORE_HALF × 2 = 0.44`）只勉强相切，
>    相邻圆盘几乎不重叠，于是一颗颗分得开，正好是**一串圆球**。
>
> 修法（只动 1.20.1，1.21.1 没这问题、保持原样）：
> - `beam_core.png` 的形状**改到 alpha 通道**上（中心 1、边缘 → 0）。alpha 混合下边缘透明、
>   轮廓消失、融成连续亮芯；加色混合（1.21.1）忽略 alpha、仍看 RGB，行为不变 —— 一改两全。
>   生成脚本见 `tools/gen_textures.py` 的 `build_beam_core()`。
> - 采样间距压到 `CORE_STEP = 0.12`（约为直径的一半），相邻亮片大幅重叠；
>   `CORE_BRIGHTNESS` 按重叠层数等比调低（0.18 → 0.075），加色总量与原来持平。

> **1.20.1 专属坑：「置空目标」会崩服（已修）**
>
> 症状：带着帽子、周围有**走 Brain 的生物**（车万女仆、猪灵、监守者这类）时，
> 服务器线程时不时崩，堆栈长这样 ——
> `Optional.of → MemoryAccessor.set → StartAttacking → Brain.tick → EntityMaid.tick`，
> 报的是 `NullPointerException: Ticking entity`，**整条堆栈里一个 hatmod 帧都没有**。
>
> 原因：本模组的 `onLivingChangeTarget` 原本用 `setNewTarget(null)` 来「拦住新锁定」。
> 这在 `Mob#setTarget`（MOB_TARGET）那条路上没问题，但 Brain 那条路是
> `StartAttacking` → `MemoryAccessor.set(event.getNewTarget())` → `Optional.of(...)`，
> **`Optional.of` 不接受 null**，于是当场 NPE。
> **1.20.1 的 Forge 补丁这一句没有判空，所以只有 1.20.1 会炸**；
> 1.21.1 的 NeoForge 补丁加了 `ifnonnull` 判空，同一个写法侥幸不崩 —— 这也是为什么之前测 1.21.1 没发现问题。
>
> 修法（两版统一）：**改成取消事件**（`HatAbilities.blockTargeting`），并且按目标类型区分：
> - `BEHAVIOR_TARGET`（Brain 抢目标）—— 无条件取消。清空走的是擦记忆，不经过这里，不会被误伤。
> - `MOB_TARGET`（`Mob#setTarget`）—— 只有「要锁**非空**目标」时取消；**置空（清目标）放行**。
>   这一条是必须的：`Mob#setTarget(null)` 自己也会走这个事件，无脑取消会让目标永远清不掉。
>
> 教训：跨加载器用同一个 EventBus 写法时，**不能假设两边的补丁行为一致** ——
> 一个「置空」在一个加载器上是合法输入、在另一个上是 NPE 的引信。

### 帽子模型 —— `client/CowboyHatModel.java`

帽檐是 **20×20** 的大宽檐（`brim`），像顶大号牛仔帽。它的贴图块画在 128×64 护甲贴图的 `(0,32)`：

| 项 | 值 |
| --- | --- |
| 帽檐尺寸 | `20 × 1 × 20`（模型单位，1 单位 = 1/16 格），`texOffs(0, 32)` |
| 护甲贴图 | `assets/hatmod/textures/models/armor/{black,white,red}_hat_layer_1.png`，**128×64** |
| 图层尺寸 | `LayerDefinition.create(mesh, 128, 64)` —— 必须和 PNG 尺寸一致 |

> 护甲贴图从 64×32 扩到了 128×64：旧内容原封不动留在左上角，`texOffs` 的像素号不变，
> 所以帽冠采样到的还是原来那几格。要再改帽檐宽度，记得重画 `(0,32)` 处的贴图块
> （宽 `2*深 + 2*宽`、高 `深 + 高`）。

> 想让光柱也能打**其他玩家**（PVP），在 `HatAbilities.isEnemy()` 里放开对
> `entity instanceof Player` 的过滤即可。

## Curios 饰品栏（可选）

装了 Curios 时，四顶帽子**也能放进饰品栏的「head」槽**，效果和戴在头盔槽里完全一样：
蓄力、照射、附魔、和平主义、音乐、光柱颜色都照常，客户端也会把帽子**画在头上**。

- **能放进饰品栏**靠物品标签 `data/curios/tags/items/head.json`（1.21 起目录名改成
  `tags/item`），里面列了四顶帽子。Curios 的 head 槽校验器 `curios:tag` 就是查这个标签，
  所以**不需要写注册代码**。
- **能生效**靠 `HatAbilities.hatStack()`：全模组「这生物戴着哪顶帽子」都走这一个入口 ——
  先看头盔槽，没有再看 Curios 饰品栏（两处都只看「是不是本模组的帽子」）。
- **能画在头上**靠 `client.CurioHatRenderer`：把父模型「头」这一节的姿态抄过来，
  用和护甲槽同一张贴图渲染同一个 `CowboyHatModel`（画法照抄原版 `HumanoidArmorLayer`）。
- **Curios 是软依赖**：没装时 `CuriosCompat` / `CurioHatRenderer` 这两个类根本不会被加载
  （调用点前面有 `ModList.isLoaded("curios")` 的守卫），所以**不装 Curios 也能正常跑**，
  只是帽子只能戴在头盔槽里。`mods.toml` 里也把 curios 声明成 `mandatory=false` 的可选依赖。
- 编译用的 Curios API 放在 `libs/curios-forge-5.14.1+1.20.1-api.jar`，走 `compileOnly`，不进成品。

> 只认 **head** 槽：戒指、腰带那些槽位放不进去（items 标签里没列它们）。
> 另外，帽子放在饰品栏时**不会掉耐久** —— 本模组那套限伤挂在护甲槽的受伤路径上，
> 而 Curios 不会替饰品扣耐久。

## 关于帽檐

牛仔帽的**宽帽檐是靠自定义模型做出来的**（`CowboyHatModel`），
因为原版头盔模型只是套在头上的一层壳，光靠 64×32 贴图画不出向外伸出的帽檐。

可以替换的贴图：

- 物品图标：`assets/hatmod/textures/item/{black,white,red}_hat.png`（16×16）
- 帽身外观：`assets/hatmod/textures/models/armor/{black,white,red}_layer_1.png`（64×32）
- 光柱贴图：`assets/hatmod/textures/particle/beam.png`（32×32，圆周方向恒定）、`beam_core.png`（64×64 圆形光斑）
- 粒子光斑：`assets/hatmod/textures/particle/flash_light.png`（16×16）
- 「神隐」的状态图标：`assets/hatmod/textures/mob_effect/veil.png`（16×16）。
- 「绿心」在 HUD 上是一条自绘的**能量条**（`client.GreenHeartRender`），不占任何贴图；
  **完全不碰原版**，所以喝吸收药水拿到的黄心还是原版黄心。
  **这个不能少**：状态效果的图标是按注册名去 `textures/mob_effect/<id>.png` 找的，
  找不到就画原版的紫黑「缺失贴图」—— 光辉一发动，状态栏就多一格错乱图标。
  贴图由 `tools/gen_textures.py` 一起生成。
